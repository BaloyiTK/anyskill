- [ ] Reconcile ambiguous Expo deliveries. If a worker crashes after an outbound request may have reached Expo but before ticket persistence, all stale claims are now moved to `UNKNOWN`, including partially ticketed multi-batch sends; existing tickets are preserved for reconciliation and are never blindly resent. This avoids automatic duplicate pushes but requires an operational reconciliation process for `UNKNOWN` records; Expo does not provide an idempotency key for send requests. 
- [x] Expo receipt polling uses bounded exponential retry scheduling, advances due times before network calls, validates response shape, expires receipts after 24 hours, and avoids starving later receipts when Expo omits a result or is unavailable.
- [x] Expo receipt lifecycle: pending receipts carry durable check-attempt counters and a next-check timestamp; polling uses bounded exponential backoff, validates Expo response shape, advances retry times before external calls, removes devices that report `DeviceNotRegistered`, and marks receipts unavailable after 24 hours. The indexed due-receipt query prevents missing early receipts or Expo outages from starving later receipts.
- [ ] Complete worker metrics and alerting. Structured worker logs include queue counts, oldest pending age, cycle duration and media cleanup count. A persisted worker heartbeat now exposes `GET /api/v1/health/worker` (healthy only when the worker has a recent heartbeat and no recorded cycle failure); monitor this endpoint on the dedicated worker deployment. Per-attempt/claim-age metrics, receipt failure detail, and external alert routing remain outstanding.
- [x] Marketplace terminal-state consistency: Seeker cancellation expires both `NOTIFIED` and `RESPONDED` matches after withdrawing outstanding offers; selecting a Provider preserves only the selected Provider's `RESPONDED` match and expires all other outstanding matches. Integration coverage includes mixed match states.

- [x] Media verification outage recovery: Cloudinary `404` confirms an absent upload, while timeouts, rate limits, authentication failures and server errors release the verification lease back to `PENDING` and return a retryable `503`; transient provider outages no longer permanently expire a valid upload reservation.
- [x] Engagement timer pause-path consistency: Providers may request additional hours during a recorded break and submit completion while paused. Completion preserves the already-checkpointed accumulated time and conditionally claims the exact running/paused timer state; no artificial resume is required.
